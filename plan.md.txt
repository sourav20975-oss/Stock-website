# Stock Knowledge SaaS — Development Plan

## 1. Project Overview

Build a responsive Stock Knowledge SaaS for Indian stock-market and IPO research.

The platform is **not a trading platform**. It is designed to help users understand:

* Indian stocks
* Live/current market data
* Historical price movement
* Upcoming IPOs
* Open IPOs
* IPO price bands
* Lot sizes
* Subscription data
* GMP
* Company financials
* Market news
* Stock comparisons
* AI-powered explanations
* Financial concepts

The product should feel like a professional Indian brokerage/research platform rather than an AI-themed application.

### Product positioning

> **Understand stocks and IPOs before you invest.**

The platform should provide factual information, educational explanations, and research tools. It should not present AI-generated content as guaranteed investment advice.

# 4. Data Strategy

The application should NOT depend on one API for everything.

## Market Data

Use Angel One SmartAPI for:

* LTP
* OHLC
* Volume
* Historical candles
* Instrument information
* Market quotes
* WebSocket price updates

## IPO Data

Collect from reliable/official sources where possible:

* IPO name
* IPO opening date
* IPO closing date
* Listing date
* Price band
* Lot size
* Issue size
* Fresh issue
* OFS
* Face value
* Reservation
* Subscription information

## GMP

GMP should be treated as:

* unofficial
* indicative
* source-dependent
* time-sensitive

Store:

```text
value
percentage
source
fetchedAt
```

Never represent GMP as an official NSE price.

## News

Store:

```text
title
description
source
url
publishedAt
symbol/company
image
```

## AI

The AI should combine:

```text
market data
+
IPO data
+
GMP
+
financial data
+
news
+
NSE MCP
```

# 7. Refresh Strategy

The application should NOT continuously call REST APIs.

Normal page load:

```text
React
  |
  v
GET /api/stocks/:symbol
  |
  v
MongoDB
  |
  v
Cached/latest data
```

Refresh button:

```text
User clicks Refresh
       |
       v
POST /api/stocks/:symbol/refresh
       |
       v
External market API
       |
       v
Fresh data
       |
       v
MongoDB
       |
       v
Frontend
```

Return:

```json
{
  "success": true,
  "data": {},
  "updatedAt": "2026-10-05T..."
}
```

---

# 8. Refresh Cooldown

Prevent API abuse.

Example:

```text
Refresh
   |
   v
API request
   |
   v
Success
   |
   v
Disable for 15 seconds
```

Backend must also enforce the cooldown.

Never rely only on frontend protection.

Example response:

```json
{
  "success": false,
  "code": "RATE_LIMITED",
  "message": "Please wait before refreshing again."
}
```

# 9. WebSocket Strategy

WebSocket should be used only for actively viewed/live market information.

Architecture:

```text
Angel One WebSocket
        |
        v
Node.js WebSocket Gateway
        |
        v
Socket.IO
        |
   +----+----+
   |    |    |
 User User User
```

## Subscription model

When a user opens:

```text
/stocks/TCS
```

subscribe to TCS.

When they leave:

```text
unsubscribe TCS
disconnect
```

Do not continuously stream every stock to every connected user.

# 14. AI Safety Rules

The AI must distinguish between:

### Facts

```text
IPO price band
Company revenue
Current market price
Subscription numbers
```

### Unofficial information

```text
GMP
```

### AI interpretation

```text
Potential strengths
Potential risks
Valuation discussion
Business explanation
```

The AI should not claim:

```text
"Guaranteed listing gain"
"Definitely buy"
"Guaranteed profit"
```

Use language such as:

```text
"According to the available data..."
"The unofficial GMP indicates..."
"Investors may want to research..."
"Potential risk factors include..."
```

# 15. Caching Strategy

MongoDB acts as the primary persistence/cache layer for the MVP.

Example:

```text
Current stock quote
    -> short-lived cache

IPO details
    -> longer cache

Company profile
    -> long cache

Historical candles
    -> update only when requested

News
    -> periodic/manual refresh

GMP
    -> manually/on-demand refreshed
```

Do not introduce Redis until it is actually needed.

---

# 16. Render Free-Tier Strategy

The platform should be designed around low background activity.

Avoid:

```text
continuous polling
large cron workloads
per-user external API polling
streaming every instrument
unnecessary background workers
```

Prefer:

```text
MongoDB cached data
+
manual refresh
+
on-demand API calls
+
WebSocket only for active users
```

When a user opens a stock:

```text
Connect WebSocket
Subscribe
Receive updates
```

When they leave:

```text
Unsubscribe
Disconnect
```
